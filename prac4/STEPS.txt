Aim: show that Schema Registry accepts a backward compatible schema change and rejects an incompatible one.

IN SIMPLE WORDS
---------------
   - A schema is the shape of a message: which fields it has and their types. Here the message is a patient record.
   - Schema Registry is a small server that stores every version of every schema. Producers and consumers ask it "what does this message look like?"
   - Schema evolution means the schema changes over time, for example a new field is added.
   - Backward compatible means: a program using the NEW schema can still read OLD messages. Old messages do not have the new field, so the new field must have a default value.
   - Rule to remember: adding a field with a default is allowed. Adding a field without a default, or changing a type (int to string), is rejected.

Think of a college form. If the new form adds "Blood group (write 'unknown' if not known)", old forms are still usable. If the new form makes blood group compulsory, all old forms become invalid.

  Version | Change                                     | Result
  --------+--------------------------------------------+------------------------------
  V1      | patient_id, patient_name, age, heart_rate  | Registered (first version)
  V2      | adds blood_pressure with default "unknown" | Accepted: backward compatible
  V3      | adds blood_group with no default           | Rejected with error 409

CODE 2 (SCHEMA_DEMO.PY), THE EASY VERSION
-----------------------------------------

Your journal uses five files (two .avsc schema files, a long Python script and two shell scripts). This single file shows the same idea. The schemas are written as Python lists, and each step is one web request to the registry.

      import json, requests
      
      URL = "http://localhost:8081"
      SUBJECT = "patient-data-value"
      HEAD = {"Content-Type": "application/vnd.schemaregistry.v1+json"}
      
      def patient(fields):
          """Build an Avro schema and wrap it the way Schema Registry wants it."""
          schema = {"type": "record", "name": "Patient", "fields": fields}
          return {"schema": json.dumps(schema)}
      
      # V1: the first schema
      v1 = [{"name": "patient_id", "type": "int"},
            {"name": "patient_name", "type": "string"},
            {"name": "age", "type": "int"},
            {"name": "heart_rate", "type": "int"}]
      
      # V2: one NEW field WITH a default value  -> backward compatible
      v2 = v1 + [{"name": "blood_pressure", "type": "string", "default": "unknown"}]
      
      # V3: one NEW field WITHOUT a default value -> NOT backward compatible
      v3 = v2 + [{"name": "blood_group", "type": "string"}]
      
      print("1. Register V1")
      print(requests.post(f"{URL}/subjects/{SUBJECT}/versions", headers=HEAD, json=patient(v1)).json())
      
      print("2. Set the rule to BACKWARD")
      print(requests.put(f"{URL}/config/{SUBJECT}", headers=HEAD, json={"compatibility": "BACKWARD"}).json())
      
      print("3. Is V2 compatible?")
      print(requests.post(f"{URL}/compatibility/subjects/{SUBJECT}/versions/latest", headers=HEAD, json=patient(v2)).json())
      
      print("4. Register V2")
      print(requests.post(f"{URL}/subjects/{SUBJECT}/versions", headers=HEAD, json=patient(v2)).json())
      
      print("5. Is V3 compatible?")
      print(requests.post(f"{URL}/compatibility/subjects/{SUBJECT}/versions/latest", headers=HEAD, json=patient(v3)).json())
      
      print("6. Try to register V3 (must be rejected)")
      r = requests.post(f"{URL}/subjects/{SUBJECT}/versions", headers=HEAD, json=patient(v3))
      print(r.status_code, r.json().get("message", "")[:80])
      
      print("7. Versions stored in the registry")
      print(requests.get(f"{URL}/subjects/{SUBJECT}/versions").json())
