Aim: count words that you type live, using Spark Structured Streaming reading from a socket.

IN SIMPLE WORDS
---------------
   - Batch processing works on data that is already complete. Streaming works on data that keeps arriving.
   - A socket is a simple connection between two programs on a port number. Here one terminal types lines on port 9999 and Spark listens on port 9999.
   - Spark treats the stream as a table that keeps growing. Each new line is a new row. Spark re-runs the count on every new batch of rows.
   - Output mode "complete" means: print the full table of counts every time, not only the changed rows.

If something goes wrong
   - Connection refused in terminal 2: Spark was started before the sender. Start socket_sender.py first, then Spark.
   - Only one usage of each socket address in terminal 1: an old sender is still running on port 9999. Close the old terminal with the bin icon and try again.
   - HADOOP_HOME and hadoop.home.dir are unset, or an error about winutils or chmod: redo setup step 8, then close and reopen VS Code.
   - Nothing happens after typing: check you pressed Enter, and that you typed in terminal 1, not terminal 2.
   - An empty word with a count appears: you typed two spaces together. The code splits on every single space.

CODE 1 (SOCKET_SENDER.PY)
-------------------------

Windows has no built-in tool to send text to a port, so this small Python program does it. It is a shorter version of the one in your journal.

      import socket
      
      # Open port 9999 and wait for Spark to connect
      server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
      server.bind(("localhost", 9999))
      server.listen(1)
      print("Waiting for Spark to connect on port 9999...")
      
      conn, address = server.accept()
      print("Spark connected! Type a line and press Enter. Type exit to stop.")
      
      while True:
          message = input("Enter message: ")
          if message.lower() == "exit":
              break
          conn.sendall((message + "\n").encode("utf-8"))   # send the line to Spark
      
      conn.close()
      server.close()
      print("Sender stopped.")

CODE 2 (WORD_COUNT_STREAM.PY)
-----------------------------

      import os
      import tempfile
      
      # Windows: give Spark a temp folder it is allowed to write to
      os.makedirs(r"C:\bigdata\prac5\spark-temp", exist_ok=True)
      tempfile.tempdir = r"C:\bigdata\prac5\spark-temp"
      
      from pyspark.sql import SparkSession
      from pyspark.sql.functions import explode, split
      
      # local[2] = 2 threads: one to receive data, one to process it
      spark = (SparkSession.builder.master("local[2]").appName("WordCount")
               .config("spark.sql.shuffle.partitions", "2")   # makes each batch fast
               .config("spark.hadoop.fs.permissions.umask-mode", "000")
               .getOrCreate())
      spark.sparkContext.setLogLevel("ERROR")
      
      # 1. Read lines from the socket. Each line arrives in a column called "value"
      lines = (spark.readStream.format("socket")
               .option("host", "localhost").option("port", 9999).load())
      
      # 2. split cuts the line into words, explode puts each word on its own row
      words = lines.select(explode(split(lines.value, " ")).alias("word"))
      
      # 3. Count how many times each word came
      counts = words.groupBy("word").count()
      
      # 4. Print the full result on the console after every batch
      query = counts.writeStream.outputMode("complete").format("console").start()
      
      query.awaitTermination()   # keep running until Ctrl+C

WHAT CHANGED FROM YOUR JOURNAL CODE
-----------------------------------
   - The temp folder is C:\bigdata\prac5\spark-temp in place of D:\prac5\spark-temp, so it works on a PC without a D: drive.
   - spark.sql.shuffle.partitions is set to 2. Without it Spark uses 200 partitions and each batch took about 20 seconds when I tested.
   - socket_sender.py is shorter, with the same behaviour.
