Aim: build a Flink stream that groups events into time windows, and sends events that arrive too late to a separate side output.

IN SIMPLE WORDS
---------------
   - Event time is when something really happened (written inside the event). Processing time is when Flink received it. Because of network delay, events can arrive in the wrong order.
   - A window cuts the stream into time boxes. A tumbling window of 10 seconds makes boxes 0 to 10 s, 10 to 20 s, 20 to 30 s, with no overlap.
   - Flink must decide when a box is complete so it can print the result. For this it uses a watermark: a marker that says "I believe all events up to this time have arrived".
   - Here watermark = (largest event time seen so far) minus 2 seconds. The 2 seconds is the waiting allowance for slow events.
   - When the watermark passes the end of a window, the window closes and its result is printed.
   - Late data = an event that belongs to a window that has already closed. Normally Flink throws it away. A side output is a second pipe that catches these late events so nothing is lost.

Think of a teacher taking attendance. She waits 2 minutes after the bell, then closes the register (the watermark passed). A student who comes after that is written on a separate late slip (the side output).

WHAT HAPPENS TO THE FOUR EVENTS
-------------------------------

The events are food delivery updates. "Order confirmed" happened at 3 s but arrives last.

  Arrives | Event           | Event time | Watermark after it | What happens
  --------+-----------------+------------+--------------------+------------------------------------------------------------------------------------------------
  1st     | Picked up       | 1 s        | about 0 s          | Goes into window 0 to 10 s
  2nd     | At restaurant   | 8 s        | 6 s                | Goes into window 0 to 10 s
  3rd     | Delivered       | 22 s       | 20 s               | Goes into window 20 to 30 s. Watermark 20 s is past 10 s, so window 0 to 10 s closes and prints
  4th     | Order confirmed | 3 s        | 20 s               | Belongs to window 0 to 10 s, which is already closed. Late: goes to side output

CODE (LATEDATA.PY)
------------------

This is "Code 2" from your journal with the missing import lines added at the top. Your journal's "Code 1" has the events in a different order (Order confirmed arrives third, before Delivered). In that order nothing is late, because the window is still open when it arrives. That is why Code 2 exists: it moves Order confirmed to the end.

      import time
      from pyflink.common import Types, WatermarkStrategy, Duration, Configuration
      from pyflink.common.time import Time
      from pyflink.common.watermark_strategy import TimestampAssigner
      from pyflink.datastream import StreamExecutionEnvironment
      from pyflink.datastream.output_tag import OutputTag
      from pyflink.datastream.window import TumblingEventTimeWindows
      
      
      # Tells Flink where the event time is: the 2nd item of each tuple
      class EventTimeAssigner(TimestampAssigner):
          def extract_timestamp(self, value, record_timestamp):
              return value[1]
      
      
      env = StreamExecutionEnvironment.get_execution_environment()
      env.set_parallelism(1)
      
      # These settings make Flink handle one event at a time,
      # so 4 test events behave like a real slow stream
      env.set_buffer_timeout(0)
      env.get_config().set_auto_watermark_interval(100)
      conf = Configuration()
      conf.set_string("python.fn-execution.bundle.size", "1")
      conf.set_string("python.fn-execution.bundle.time", "1")
      conf.set_string("python.operator-chaining.enabled", "false")
      env.configure(conf)
      
      # (status, event time in milliseconds). "Order confirmed" arrives LAST
      events = [
          ("Picked up", 1000),
          ("At restaurant", 8000),
          ("Delivered", 22000),
          ("Order confirmed", 3000),
      ]
      data = env.from_collection(
          events, type_info=Types.TUPLE([Types.STRING(), Types.LONG()]))
      
      
      # Wait 1 second between events, like a slow network
      def slow(e):
          time.sleep(1)
          return e
      
      
      data = data.map(slow, output_type=Types.TUPLE([Types.STRING(), Types.LONG()]))
      
      # WATERMARK: allow events to be up to 2 seconds out of order
      watermarks = (WatermarkStrategy
                    .for_bounded_out_of_orderness(Duration.of_seconds(2))
                    .with_timestamp_assigner(EventTimeAssigner()))
      stream = data.assign_timestamps_and_watermarks(watermarks)
      
      # SIDE OUTPUT: a label for the pipe that catches late events
      late_tag = OutputTag("late_events",
                           Types.TUPLE([Types.STRING(), Types.LONG()]))
      
      # WINDOW: 10-second tumbling windows, late events go to late_tag
      windowed = (stream
                  .key_by(lambda event: "delivery", key_type=Types.STRING())
                  .window(TumblingEventTimeWindows.of(Time.seconds(10)))
                  .side_output_late_data(late_tag))
      
      # Join the names of all events that fell in the same window
      main = windowed.reduce(
          lambda a, b: (a[0] + " + " + b[0], max(a[1], b[1])),
          output_type=Types.TUPLE([Types.STRING(), Types.LONG()]))
      
      late = main.get_side_output(late_tag)
      
      main.map(lambda e: "MAIN OUTPUT (window result): " + str(e),
               output_type=Types.STRING()).print()
      late.map(lambda e: "SIDE OUTPUT (late event): " + str(e),
               output_type=Types.STRING()).print()
      
      env.execute("Food Delivery Late Data")
